# 15 September 2026

## fix/audit-medium-low-findings

1.

   - Before: Teacher question edits could persist options and correct-answer data that the deterministic grader cannot score, silently marking valid student answers wrong.
   - After: The edit endpoint loads the teacher- and tenant-owned question, validates the complete post-edit answer shape before writing, and has regression coverage for valid, invalid, partial, and cross-tenant edits.

2.

   - Before: Institution analytics dialogs declared modal ARIA semantics without initial focus, a keyboard focus trap, or focus restoration.
   - After: The shared Dialog primitive now manages focus and the four analytics drill-down dialogs use it consistently while retaining Escape and backdrop close behavior.

3.

   - Before: Generation rollback deletes and document processing status writes relied on internal identifiers without repeating tenant and owner constraints.
   - After: Every affected service-role cleanup and status write includes explicit tenant and creator/uploader guards.

4.

   - Before: Admin directory reads could hit implicit PostgREST row ceilings, and email resolution retained every Supabase Auth user even when only a small tenant-scoped subset was needed.
   - After: Teacher, assignment, subject, course, enrollment, and roster reads use explicit paged collection reads, while Auth email resolution retains only requested profile IDs and stops as soon as they are found.

5.

   - Before: The public signup-course endpoint accepted arbitrary tenant strings and did not state its intentionally public data boundary.
   - After: It requires a UUID tenant identifier and documents that only public registration metadata (course IDs and names) is returned; malformed identifiers are regression-tested.

6.

   - Before: The frontend displayed rate-limit text but discarded the backend's machine-readable `Retry-After` response header.
   - After: `ApiRequestError` exposes a normalized `retryAfterSeconds` value for countdowns and action disabling without changing existing messages.

7.

   - Before: A slow review-detail response could update state after navigation, and document uploads buffered the complete body before enforcing the 30 MiB ceiling.
   - After: Review loading ignores stale/unmounted responses, and uploads read at most the configured limit plus one byte before rejecting oversized files.

8.

   - Before: Comments and deployment guidance inaccurately attributed service-role question filtering to RLS and conflated HS256 secret verification with ES256/RS256 JWKS verification.
   - After: The documentation now matches the actual application filtering, Railway backend, Vercel frontend, and JWT verification paths.
