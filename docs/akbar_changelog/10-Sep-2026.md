# 10-Sep-2026

## fix/dashboard-client-cache

1.

   - Before: Student, teacher, institution-admin, and super-admin landing dashboards unconditionally fetched their complete payload again whenever their components remounted.
   - After: SWR caches each role dashboard payload inside the authenticated dashboard layout, deduplicates requests for 60 seconds, renders cached data immediately on return navigation, and discards the cache when the dashboard session unmounts.

2.

   - Before: `html-to-image` was part of every quiz attempt's initial JavaScript even though students only use it after grading when downloading a score card; attempt and practice routes each loaded 192 kB initially.
   - After: `html-to-image` loads only when image export is requested, reducing the measured first-load JavaScript for both attempt routes from 192 kB to 187 kB.

3.

   - Before: The codebase had no server-state cache package, and adopting a larger mutation-oriented query framework would add configuration beyond these read-heavy dashboards' needs.
   - After: Added SWR as the lightweight fit for cached GET requests, retaining existing retry UI and parallel fetch behavior without a global query-client setup.

4.

   - Before: Findings #3 (super-admin aggregation) and #5 (missing indexes) were identified alongside the current performance work.
   - After: Both performance findings remain explicitly pending for the requested follow-up round and are unchanged on this branch.
