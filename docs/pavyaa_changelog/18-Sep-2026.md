# 18-Sep-2026

## testing-pavyaa

1.

   - Before: When student signup failed, the page always showed a generic "Account creation failed. Please check your details and try again.", hiding the real Supabase/GoTrue reason — so the failure was impossible to diagnose.
   - After: The signup page now surfaces the actual error message (e.g. an email rate-limit or confirm-email send failure) and logs it to the console. (The reported "cannot create any student account" outage was traced to Supabase "Confirm email" being ON with no SMTP configured — a mail-send limit, not a code bug; resolved by turning Confirm email off. The database trigger, schema, and tenant were all verified healthy.)

2.

   - Before: The public signup course dropdown (`GET /api/v1/public/courses`) listed a tenant's courses filtered only by tenant, while the `handle_new_user` signup trigger derives the tenant only from an ACTIVE institution — a mismatch that could make every signup fail with a generic error if the institution were inactive.
   - After: `public_courses` now joins `tenants` and returns only courses whose institution is `is_active = true`, so the dropdown never offers a course that the signup trigger would then reject.

3.

   - Before: There was no way to measure AI question-generation quality across subject domains (commerce, biology, maths, tech, competitive, arts).
   - After: An internal **quiz-quality evaluation harness** was built (LLM-as-judge using GPT-4o via OpenRouter, one 20-year "expert examiner" persona + rubric per domain, runs the real generator on sample documents and grades every question, producing a downloadable HTML report with per-domain scores and cost per quiz set). NOTE: this harness is an internal QA tool and is intentionally **NOT included in this commit / push** — it is not product code.
