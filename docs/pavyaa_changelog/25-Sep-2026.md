Hotfix: students could not start any quiz on the live deployment — every "start
attempt" returned HTTP 500. Root cause was a response-model mismatch on `main`

Validation: 69 student/attempt tests passing; reproduced the exact production
failure against the model and confirmed the fix resolves it.

1. Fix 500 on starting a quiz attempt (production-wide student outage)

   - Before: `_strip_answer` includes a `figure_id` on every question sent to the student, but the `TakingQuestionOut` response model (base `extra="forbid"`) did not declare `figure_id`. FastAPI validates its own response, so the server built the quiz and then rejected it with `extra_forbidden` on `figure_id` → 500 on `POST /api/v1/attempts`. Results (`ResultQuestionOut`, which extends the same model) had the same latent fault. The unit tests call the endpoints as plain functions, which bypasses response-model validation, so the fault only surfaced over real HTTP.
   - After: Added `figure_id: str | None = None` to `TakingQuestionOut`. The response now accepts (and preserves) the field the code already emits, so attempts start normally and results serialise correctly. Additive and behaviour-neutral otherwise — no migration, no config change.
