# 12-Sep-2026

## topic-pavyaa

1.

   - Before: The "same document uploaded again" warning existed only on the Extract-Quiz (question-paper) feature; the generate-a-quiz flow (`/documents/upload`) neither computed nor checked a content hash, so re-uploading the same study document produced no warning at all.
   - After: `POST /api/v1/documents/upload` now stores the file's SHA-256 `content_hash` on every upload (reusing the `documents.content_hash` column from migration-17), so re-uploads of the same file can be detected.

2.

   - Before: There was no way to tell a teacher they were about to re-use a document they had already uploaded for the same subject and chapter.
   - After: A new `POST /api/v1/documents/check-duplicate` endpoint (teacher-only, subject-ownership enforced) resolves the chosen subject + chapter, files the current document under that chapter, and reports whether another same-content document is already filed there — returning the previous file's name and upload date. It is a warning only and never blocks; a missing/legacy content hash is backfilled on the fly and a check failure degrades silently.

3.

   - Before: In the blueprint generator, uploading the same document again under the same subject and chapter gave the teacher no feedback.
   - After: When the teacher clicks "Extract topics" (subject + chapter + document all chosen), the UI calls the duplicate check and, if the same file is already filed under that subject + chapter, shows a dismissible amber warning banner ("You've already uploaded this document … under this subject and chapter … Generating again will create a duplicate quiz."). Extraction and generation still proceed normally — the warning is non-blocking. The banner is cleared whenever the selected document changes.

4.

   - Before: The blueprint generator distributed questions across topics with a confusing High/Medium/Low weighting (relative 3:2:1 units over a ~70% emphasis pool), so the same "High" could mean anything from 33% to 70% depending on the mix, and a single selected topic ignored the weight entirely.
   - After: The weightage is now explicit per-topic, per-format counts. `BlueprintTopicIn.counts` (e.g. `{"mcq_single": 2, "fill_blank": 1}`) is accepted by both `/quiz-sets/generate-blueprint` and `/generation-jobs/{id}/generate`; a shared `_resolve_blueprint_plan` helper validates the formats, sums each topic, and aggregates the total. When any topic carries counts, `build_blueprint` bypasses the weight math, builds the quiz only from the selected topics (no general coverage), and the prompt lists an exact per-topic plan while the existing exact-mix enforcement guarantees the aggregate type totals.

5.

   - Before: If no topic was selected the flow still worked; that whole-document behaviour must be preserved.
   - After: The logic is an explicit if/else — no topic selected keeps the current whole-document flow (global per-type counts, general coverage), while selecting any topic switches to the new per-topic flow. Per-topic mode implies selected-topics-only automatically for both the small-document and large-document (job) paths.

6.

   - Before: After topics were extracted the teacher was shown the topic list and a global type-count container, with no guidance and a weight-based selector.
   - After: The teacher UI was reworked: a one-time informational pop-up ("Topics ready!") explains the next steps without collecting any data; container 1 holds the overall total, difficulty and style; each selected topic expands inline to per-format count steppers; a live "X / N allocated" meter shows the running sum and Generate is blocked until the per-topic counts equal the total. If no topic is selected the legacy global per-type steppers are shown instead.

7.

   - Before: On the Generate page the "Quiz options" card (total, difficulty, style) sat below the topics list, so the teacher set the options after picking topics.
   - After: The Quiz options card now renders above the topics list, so the teacher sets the total, difficulty and style first, then distributes those across the topics.

8.

   - Before: The "Generate quiz" button lived inside the Quiz options card which, now at the top, forced the teacher to scroll back up after selecting topics.
   - After: The Generate button was moved to the very bottom of the page (after the topics card) with an inline hint explaining why it stays disabled until the per-topic counts add up to the total, giving a natural top-to-bottom flow.
