# 24-Sep-2026

## mrtp-pavyaa

Knowledge base for exam papers - PYQ (Previous Year Questions), MTP (Mock Test
Papers) and RTP (Revision Test Papers) - built on the quiz extraction flow.
Everything is additive and gated behind `PAPER_BANK_ENABLED` (default off;
`PYQ_ENABLED` kept as a legacy alias) PLUS a per-upload teacher opt-in. With the
flag off, or the teacher answering "No", extraction / review / publish / generation
and the student dashboard are byte-for-byte what they are today. Requires migrations
60-61. Validation: 732 backend tests passing + clean frontend typecheck (only the
pre-existing Windows-only cp1252 test failures remain).

1. Generalised knowledge base data model

   - Before: There was no store for classified exam questions; extraction only ever produced a normal quiz, and PYQ was a lossy placeholder (year embedded in the explanation text).
   - After: Added migration 61 - one `paper_questions` bank for all three types (`paper_type` in pyq/mtp/rtp, subject + chapter scoping, exam/year, dedup by content+year+exam, descriptive `model_answer`/`answer_summary`, tenant-safe RLS). Generalised the questions PYQ columns into `paper_*` columns and added `documents.contains_papers`. Renamed the flag `PYQ_ENABLED` -> `PAPER_BANK_ENABLED` (legacy alias retained). Behaviour-neutral.

2. Teacher opt-in + PYQ/MTP/RTP classification on import

   - Before: The extractor pulled MCQs out of a document with no notion of what kind of paper it was.
   - After: The Import screen shows a checkbox "This document contains PYQ / MTP / RTP questions". When ticked (and the flag is on), the AI classifies every question as pyq/mtp/rtp with year/exam, using a document-level context pass so a first/last-page label reaches questions in every chunk. When unticked -> today's extraction, byte-for-byte. Threaded through the API -> durable worker -> prompt; the paper columns are persisted via a safe post-commit update (the atomic RPC is untouched).

3. Descriptive extraction + AI grading (makes MTP/RTP real)

   - Before: The extractor skipped descriptive/subjective questions entirely, so mock and revision papers (which are largely subjective) imported nothing - "No usable questions found".
   - After: In paper mode the AI also extracts descriptive questions with their model answer plus a concise key-point `answer_summary`. A descriptive question is stored with a placeholder correct_answer (so the NOT NULL column accepts it - no schema change) and enters the bank only if it has a model answer/summary. At student submit, all descriptive answers are graded in one batched AI call: the student's answer is compared to the model summary and earns the marks when it covers >= 90% of the key points, else zero. Best-effort: if the grader is unavailable, descriptive shows pending (0) but the objective score still finalises. Objective types are graded deterministically as before.

4. Student "Mock Test & PYQ"

   - Before: Students had no way to practise previous-year / mock / revision questions.
   - After: A new student surface with three tabs (PYQ / MTP / RTP): pick a subject, then optionally a chapter, question type and how many questions; the server pulls a RANDOM matching set from the bank (subject-scoped to the student's enrolment) and grades it into a scorecard (objective auto-graded + descriptive AI-graded, with correct answers shown). Descriptive questions use a free-text answer box.

5. Teacher "Paper bank" log + review cleanup

   - Before: Teachers had no visibility into what their published papers contribute to students, and the review queue printed a verbose source-inventory coverage report ("Not matched - source question N ... [PYP 2024 Q60]", per-page manifest) that cluttered the page.
   - After: New teacher "Paper bank" page (Content) showing PYQ/MTP/RTP totals and per-subject counts of what is in the student bank, backed by a staff-only `GET /api/v1/papers/bank`. Review shows each question's paper-type badge (PYQ/MTP/RTP . year . exam) and, for descriptive, the model answer. The noisy source-inventory report was removed; the review now shows only the questions, plus a concise "Import receipt" collapsible that appears only when some candidates were skipped. Publish snapshots each approved, classified, gradeable question into the bank (deduped, subject+chapter scoped).

   Activation: apply migrations 60-61, set `PAPER_BANK_ENABLED=true`, restart the backend. Then import a paper with the box ticked -> review (badges) -> publish -> it appears in the teacher Paper bank and the student Mock Test & PYQ tab. Descriptive extraction works best on documents that contain the questions (ideally with suggested answers), not answer-key-only files.
