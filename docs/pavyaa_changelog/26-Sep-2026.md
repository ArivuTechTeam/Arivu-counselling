# 26-Sep-2026

## mrtp-pavyaa

A large session of additive features and UI/UX uplift. Everything is
frontend-only or flag-gated and behaviour-neutral when off; the backend AI/core
is untouched by the UI work. Validation: full backend suite green except the
known pre-existing Windows cp1252 / stray-file failures; frontend typecheck
clean; 52 frontend unit tests passing.

1. Reject = reversible grey mark, permanent delete only at publish

   - Before: Rejecting a question soft-flagged it forever; rejected rows piled up in the DB.
   - After: In the review queue a rejected question greys out (text only) and the Reject button becomes Un-reject; nothing is deleted until Publish. At publish, if any questions are rejected a confirm modal warns "N will be deleted permanently"; on confirm the rejected questions are hard-deleted (children cleaned first; a question ever answered by a student is preserved; each purge writes an audit event). Flag `REJECTED_PURGE_ENABLED` (default off). No migration.

2. Extraction blueprint (publish a chosen subset of extracted questions)

   - Before: Extraction published everything; a 259-question document dumped all 259 on students.
   - After: A "Publish blueprint" panel on the review page shows the document's PYQ/MTP/RTP counts and lets the teacher pick a total and per-type counts; the app randomly samples exactly those (no AI), with "Shuffle again" and "See selected" (filters the review list to the picked questions so they can be read/edited before publishing). Only the selected are approved+published; the rest stay untouched in the DB for later. Unclassified documents degrade to "pick a random N", with a hint to re-import with the PYQ/MTP/RTP box ticked. Flag `EXTRACTION_BLUEPRINT_ENABLED`. No migration.

3. Descriptive questions are approvable

   - Before: `validate_question_answer_shape` had no case for `descriptive`, so approving/publishing a descriptive (MTP/RTP) question failed with "unsupported question type: descriptive".
   - After: Descriptive is accepted (it is AI-graded against the model answer, not shape-checked). Fixes individual approve, approve-all, and blueprint publish for descriptive.

4. Regenerate the whole quiz

   - Before: Only per-question regenerate existed.
   - After: A "Regenerate quiz" action on a draft rebuilds every question with a fresh AI version (same shape), reusing the per-question logic but recovering the source material ONCE per set and running with bounded concurrency; best-effort (a failed question keeps its old content). Draft-only, owner-scoped, rate-limited, `REGENERATE_SET_ENABLED`. Also fixed a latent 500: source recovery used `.maybe_single()` on `quiz_generation_jobs`, which crashed when a set had more than one generation job (now takes the most recent blueprint-carrying job). No migration.

5. Teacher UI/UX (Phase 0)

   - Before: When distributing questions across topics against a total, the teacher lost track of how many were allocated; batch assignment lived only on the Published Quizzes screen.
   - After: A sticky live "allocation meter" (`AllocationMeter`) rides the top of the topic list showing assigned/target, remaining, and a per-type breakdown that updates as they type. Assign-to-batches now also appears in the review/publish flow (content-first), and the review action bar wraps so buttons never clip.

6. Student test player (Phase 2)

   - Before: A plain question list with a 3-state palette; no rough-work aid.
   - After: The standard 5-state question palette (not visited / not answered / answered / marked / answered+marked); a Focus mode that hides the palette; per-question time tracked in the browser (for the results analysis); and an inline "Rough work" panel under the palette with Notes (scrollable, saved per attempt until submit), a safe Calculator (custom parser, never `eval`), and a freehand Draw pad.

7. Student "Smart Analysis" results (Phase 3)

   - Before: The results screen was mostly a score plus per-question cards (explanations only when wrong).
   - After: A diagnostic report (`quiz-analysis.ts` + `QuizAnalysisReport`) computed entirely client-side: correct/wrong/skipped + accuracy + score, a by-question-type breakdown (weakest first), Embibe-style attempt-quality tags (Perfect / Slow-but-right / Rushed / Struggled) from the tracked time, a time-vs-accuracy split, plain-English coaching lines, a Solutions filter (All / Incorrect / Marked) with per-question time and always-visible explanations, and a "What's next" card. Per-question topic/difficulty analytics are intentionally deferred (they need a small backend addition).

8. Student discovery & engagement (Phase 4)

   - Before: The quiz list only split into to-take vs completed with no way to find a specific quiz; completed quizzes were a plain list; the daily streak had no milestone or celebration; history had no trend; PYQ/MTP/RTP were minimal text tabs.
   - After: The Take-Quiz list gets search + subject filter + sort (Newest / Title / Attempts left) with a filter-aware empty state, and completed quizzes lead with a colour-coded best-score badge. The Daily Challenge shows a "Next milestone" progress bar (3/5/7/14/30/50/100 days) and fires a one-time `SparkBurst` celebration when today's challenge pushes the streak to a new high (deduped via localStorage). Quiz history gains a "Score trend" summary with a lightweight SVG `MiniSparkline` (last 10 scores) plus a plain-English read ("up 12%" / "down 8% - time to revise") with average and best. The PYQ / MTP / RTP selector becomes three distinct colour-coded bucket cards (icons + full names + one-line descriptions) matching the ICAI taxonomy.

9. Teacher polish (Phase 1)

   - Before: No keyboard control in the review queue; the extraction wait said only "this can take several minutes, don't close this tab"; the published-quiz metric "Average" was ambiguous.
   - After: Review-queue keyboard shortcuts (A/P/R/E to filter by status, 0 for all; ignored while typing) with a subtle on-screen hint. The extraction "reading your document" state shows a live elapsed timer and calmer copy ("usually 1-5 minutes - keep this tab open, you can switch tabs"). Published-quiz metrics renamed for clarity ("Average" -> "Avg. accuracy", "Highest/Lowest ... accuracy") with hover hints defining every column. (A blanket control-height restyle and a nav-label rename were intentionally skipped as cosmetic/higher-risk for low payoff.)
