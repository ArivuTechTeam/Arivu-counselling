# 9-Sep-2026

## notify-pavyaa

1.

   - Before: Approving or rejecting a question in the review queue only flipped a small status badge silently, so teachers could not tell an action had registered.
   - After: Approving a question fires a spark burst, a green card flash, and a solid green "Approved" button, while rejecting shows a red shake, red ring, and a red Reject button, with the status badge popping and the accent strip transitioning smoothly.

2.

   - Before: Big one-off actions (Publish, Approve-all, Extract, Generate) gave no visible confirmation that they succeeded.
   - After: Each big action shows a toast pop-up (via the new dependency-free ToastProvider/useToast, mounted once in the dashboard layout), and Publish and Approve-all also fire a spark burst on the action bar, avoiding a mess of per-item pop-ups.

3.

   - Before: The new pop-up and animation effects risked being distracting or inaccessible to users who prefer reduced motion.
   - After: New spark-fly, approve-pop, reject-shake, badge-pop, and toast-in keyframes plus the spark-burst component are deterministic and guarded by prefers-reduced-motion.

4.

   - Before: The forced first-login password change accepted any 8-character password with only a confirm-match, performed no current-password check, and left the user stranded in a stale dashboard with empty or error data.
   - After: The change-password endpoint requires and verifies the current password, blocks reusing the current password, and enforces a strong server-side policy (>=8 chars including upper/lower/number, not the email or email-name, not a common password).

5.

   - Before: The change-password modal only asked for a new password and confirmation with no live guidance.
   - After: The modal was rewritten to Current + New + Confirm with a live requirements checklist that gates submission until every rule passes, backed by an updated changePassword(current, new) API call.

6.

   - Before: A forced first-login password change left the user authenticated with stale session data.
   - After: A forced change now signs the user out and redirects to /login?reason=password-changed so they re-authenticate cleanly, with the login page showing a friendly "password changed, please sign in" notice; voluntary changes just close the modal.

7.

   - Before: The strong password rules had no test coverage locking their behavior.
   - After: New backend PasswordPolicyTests in test_security_regressions.py lock the password validation rules.

8.

   - Before: The teacher Subjects tab was a plain list of subject names with no metrics.
   - After: A new tenant- and teacher-scoped GET /api/v1/teacher/subject-metrics endpoint (bulk-aggregated, no N+1) powers a rebuilt per-subject analytics dashboard with a KPI strip, a "to review" banner, and per-subject cards (avg-score bar, activity line, metric grid, and published/draft/to-review chips), while "Manage chapters" still opens the unchanged ChapterManager.

9.

   - Before: The teacher dashboard had accuracy, pipeline, and roster analytics but no time-series trend or score distribution.
   - After: GET /api/v1/teacher/class-overview now returns activity_trend (quizzes taken per day over the last 14 days, zero-filled) and score_distribution (0-40/40-60/60-80/80-100 bands) computed in memory with no new queries, rendered as new "Activity — last 14 days" and "Score distribution" chart cards in class-analytics.tsx.
