# 11-Sep-2026

## ocr-pavyaa

1.

   - Before: All quiz generation ran as a single synchronous LLM call over the document text truncated to the generation character limit, so documents beyond ~40 pages either lost their tail to truncation or timed out on one huge request.
   - After: A new `POST /api/v1/quiz-sets/analyze` endpoint measures the extracted text against `CHUNKING_TRIGGER_CHARS` (default 100,000) and routes accordingly: small documents return topics inline (`"direct"` mode) while large documents open a resumable background job and return a `job_id` immediately (`"job"` mode).

2.

   - Before: There was no persisted generation state, so a long generation had nowhere to checkpoint and could not resume after a process restart.
   - After: `migration-24-chunked-generation-jobs.sql` and `migration-24b-reset-chunked-generation.sql` add the `quiz_generation_jobs` and `document_chunks` tables (with `generation_job_status`/`map_status` enums), and a daemon-thread `GenerationJobRunner` drives each job through the phases `chunking → mapping → reducing → ready`, updating status (`queued/running/partial/completed/failed`) and done/total chunk counts as it progresses.

3.

   - Before: N/A — large-document handling did not exist.
   - After: Each large document is profiled once (subject + summary, best-effort) by `document_profile.py`, then split by the chunking service into overlapping, SHA-256-hashed chunks (`GENERATION_CHUNK_CHARS` / `_OVERLAP_CHARS` / `_MIN_CHARS`) stored in `document_chunks`; re-runs skip already-stored chunks, making chunking idempotent and resumable.

4.

   - Before: N/A.
   - After: `topic_extraction_pipeline.py` (MAP phase) extracts structured study content — topics, definitions, key facts, formulas, worked examples — from each queued/failed chunk using a bounded thread pool (`GENERATION_CHUNK_CONCURRENCY`, default 4), atomically claiming each chunk, retrying once on failure, and marking it `succeeded`/`failed`.

5.

   - Before: N/A.
   - After: `master_blueprint_synthesizer.py` (REDUCE phase) consolidates every succeeded chunk's topics into one de-duplicated master blueprint (verbatim definitions/formulas/examples preserved), stored on the job; the job finalizes as `completed` when all chunks mapped, or `partial` when some failed (blueprint still usable and retryable).

6.

   - Before: Blueprint generation persisted questions inline inside `generate_blueprint_quiz`, coupling the question writer + persistence to a single small-document text source.
   - After: `blueprint.py` was refactored to a shared `generate_and_persist_from_material` used by BOTH paths; `quiz_generator_service.py` renders the master blueprint back to material text and reuses the identical writer, validation, and persistence, so large-document quizzes flow through the exact same teacher review → publish pipeline as small ones.

7.

   - Before: N/A.
   - After: `GET /api/v1/generation-jobs/{id}` exposes status, phase, progress, and topics for the frontend to poll; `POST /generation-jobs/{id}/retry` relaunches `failed`/`partial` jobs (skipping already-done chunks); `POST /generation-jobs/{id}/generate` produces the final quiz once the job is ready.

8.

   - Before: Structured JSON calls used the default model output budget, which silently truncated the large verbatim MAP/REDUCE JSON mid-response.
   - After: `structured.py` adds `complete_json_large` with a raised output-token budget (`GENERATION_MAP_MAX_OUTPUT_TOKENS`, default 65536) and "thinking" disabled so the whole budget goes to output; `DEEPSEEK_MAX_OUTPUT_TOKENS` was also raised above the 4096 default so the DeepSeek fallback isn't cut off.

9.

   - Before: N/A.
   - After: `config.py` adds the env-tunable levers for the pipeline — `CHUNKING_TRIGGER_CHARS`, `GENERATION_CHUNK_CHARS`, `GENERATION_CHUNK_OVERLAP_CHARS`, `GENERATION_CHUNK_MIN_CHARS`, `GENERATION_CHUNK_CONCURRENCY`, `GENERATION_MAP_MAX_OUTPUT_TOKENS`, `GENERATION_PROFILE_MAX_CHARS`, `GENERATION_CHUNK_STUCK_SECONDS` — all changeable from Railway with no code change.

10.

   - Before: The teacher blueprint generator sent one `generate` call and waited on a single blocking request.
   - After: `blueprint-generator.tsx` and `lib/api.ts` now call `/analyze`, poll the generation job until topics are ready (showing progress), then trigger final generation — so large documents no longer block or time out on one request.

11.

   - Before: The generation pipeline internals had no automated test coverage.
   - After: Ten new backend test files cover the chunking service, document profile, generation chunking, generation jobs, topic-extraction pipeline, master-blueprint synthesizer, quiz-generator service, and the generation API.

12.

   - Before: The large-document generation approach was undocumented.
   - After: Added decision and design docs — `ai-quiz-generation-large-docs-decision.md`, `chunked-generation-architecture.md`, `chunked-generation-build-plan.md`, `llm-prompts.md`, `rag-approach-assessment.md` — plus the `ocr-feature-decision.md` research brief.
